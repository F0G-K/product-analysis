| 评分锚点 | 各维度 1-5 分对应的具体判定标准，作为大模型评分的参照依据，确保同维度下不同需求之间评分可比 |

| 多因素认证（MFA） | 在用户名和密码之外增加第二验证因素（如 TOTP 动态码、短信验证码或硬件密钥）的身份确认机制 |

## 2. 产品概述

### 2.1 背景与问题

产品团队在需求决策、研发交付和上线复盘三个阶段存在连续的信息断层。

需求决策阶段，优先级往往由经验、职位或临时压力决定。不同需求缺少统一评价维度，评分依据不可追溯，导致高价值需求被延后、低价值需求挤占产能，排期争议反复发生。

研发交付阶段，PRD、原型、接口、埋点与测试用例由不同角色维护，版本和表达方式不一致。字段定义、状态流转、权限、异常处理及验收条件容易出现冲突或遗漏，问题通常在联调、测试甚至上线后才暴露，返工成本高。

上线运行阶段，异常信息散落在监控、日志、工单、代码仓库和项目文档中。问题定位依赖人员经验，难以快速判断来源属于需求遗漏、设计缺陷、实现错误、配置变更还是数据异常，延长恢复时间，也削弱复盘质量。

本产品以大语言模型（LLM）为分析引擎，遵循”统一输入、规则分析、证据可追溯、人工决策”原则，为产品全生命周期提供三个协同助手，不代替业务责任人做最终决策。

### 2.2 产品定位

产品管理智能助手平台是一套以大语言模型为核心分析引擎、面向产品研发团队的决策与质量辅助工具。平台将大模型的语义理解与可配置规则体系结合，连接需求和研发过程中的结构化、非结构化材料，将分散信息转化为可解释的评分、问题清单和归因建议，降低主观决策、交付偏差及线上定位成本。

### 2.3 产品目标

V1.0 聚焦以下目标：

- 建立统一、可配置、可追溯的需求价值评估机制。
- 在研发进入测试前发现关键交付物之间的冲突与遗漏。
- 汇总指定上线版本的多源信息，输出带证据和置信度的问题归因建议。
- 形成从需求决策、交付检查到上线复盘的闭环记录。
- 保留人工确认节点，确保关键结论有明确责任人。

### 2.4 非目标

V1.0 不包含以下能力：

- 不替代项目管理、缺陷管理、代码托管、监控或日志平台。
- 不自动决定需求是否立项、版本是否发布或线上问题责任归属。
- 不直接修改外部系统中的 PRD、接口、代码、测试用例或生产配置。
- 不承诺覆盖图片像素级原型比对、源码级缺陷定位及根因自动修复。
- 不建设通用企业知识库，仅管理完成三类分析所需的资料、索引和结果。
- 不支持跨组织公开共享数据，所有数据均在租户与项目权限内使用。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户角色 | 核心诉求 | 主要操作 |
| --- | --- | --- |
| 产品负责人 | 统一判断需求价值，减少排期争议 | 配置评估模型、审批评分、查看需求组合 |
| 产品经理 | 提交完整需求，定位交付物差异 | 发起评估、补充证据、处理一致性问题 |
| 研发负责人 | 提前识别接口、流程及实现风险 | 查看检查结果、确认影响、参与归因 |
| 测试负责人 | 确保测试用例覆盖需求与异常分支 | 发起检查、认领问题、复核关闭 |
| 数据人员 | 确保埋点口径和指标定义一致 | 处理埋点字段、触发时机及口径问题 |
| 运维或 SRE | 快速聚合异常信号，缩短定位时间 | 创建归因任务、补充日志和监控证据 |
| 项目管理员 | 维护项目、成员、数据源和规则 | 配置连接、权限、模板及通知 |
| 管理者 | 查看产品决策和交付质量趋势 | 查看汇总看板，不参与具体编辑 |

### 3.2 核心场景

#### 3.2.1 需求评审前

产品经理将已进入需求池的需求提交评估，大模型依据预设的维度体系和评分锚点，理解需求描述并生成各维度评分和解释。产品负责人查看证据和敏感性分析，确认或修正优先级，结果用于版本规划。

#### 3.2.2 研发提测前

产品经理或测试负责人选择同一需求关联的 PRD、原型说明、接口文档、埋点方案和测试用例，创建检查基线。大模型结合检查规则对多份文档进行语义级比对，识别跨文档不一致项，责任人完成修正或说明后复检，阻断级问题清零后进入提测。

#### 3.2.3 上线异常发生后

运维或研发负责人选择上线版本和异常时间窗，关联日志、监控指标、工单、代码变更、测试记录及需求文档。大模型按时间线聚合多源信息，提取证据并匹配归因类别，生成候选归因及证据链，负责人确认主要来源和处置建议，结果进入问题复盘。

### 4.2 核心对象关系

一个租户包含多个项目，一个项目包含多个需求和发布版本。需求可以关联多份交付物，并产生多次价值评估与一致性检查。发布版本关联一个或多个需求、代码变更和测试记录；线上异常归属于指定发布版本，并可产生多次归因分析。所有任务均保存输入快照、规则版本、分析结果、人工操作与最终状态。

## 5. 总体业务流程

### 5.1 任务通用状态

所有分析任务采用统一状态：

- 草稿：任务尚未提交，可修改输入。
- 待校验：系统校验输入完整性及数据源可用性。
- 分析中：系统锁定输入快照并执行分析。
- 待确认：分析完成，等待责任人处理或确认。
- 已完成：人工确认结束，形成正式结果。
- 失败：因数据、权限或系统错误未完成分析，可修复后重试。
- 已取消：任务创建人主动终止，保留记录但不计入正式指标。

已提交任务不得直接替换输入材料。材料更新后应创建新基线或新分析版本，确保历史结论可复现。

## 6. 功能需求

### 6.0 用户认证与登录

#### 6.0.1 概述

用户认证模块是平台的安全入口，负责用户身份验证、会话管理和访问控制。平台支持本地账号和 SSO 两种认证方式，并提供多因素认证增强安全性。认证通过后，用户会话受超时和并发策略约束；所有登录活动纳入审计日志。

#### 6.0.2 账号注册与激活

**租户创建：** 平台采用租户隔离模型。租户由系统管理员在后台创建，创建时需指定租户名称、管理员账号（邮箱）和初始密码。租户管理员登录后可自行创建项目、邀请成员。

**成员加入：**
- 租户管理员或项目管理员通过邮箱发送邀请链接。
- 被邀请人点击链接后设置密码并激活账号，链接有效期 48 小时。
- 支持批量导入成员（CSV 格式），导入后系统批量发送激活邮件。

**自助注册：** V1.0 不支持公开自助注册。所有账号由租户管理员或系统管理员创建。

#### 6.0.3 登录

**登录方式：**

| 方式 | 适用场景 | 说明 |
| --- | --- | --- |
| 邮箱 + 密码 | 默认方式 | 所有用户均可用 |
| SSO（SAML 2.0 / OIDC） | 企业已部署 IdP | 租户管理员配置 IdP 元数据后启用；支持一键跳转企业登录页 |
| LDAP | 企业内网环境 | V1.0 可选支持 |

**登录流程：**
1. 用户访问平台登录页，选择登录方式。
1. 输入凭据（或跳转 IdP 完成认证）。
1. 若启用 MFA 且为首次登录，引导用户绑定 TOTP 应用。
1. 若已绑定 MFA，输入一次性动态码。
1. 系统校验凭据和会话策略，创建会话并跳转至工作台。

**登录安全策略：**
- 连续 5 次失败后，账号锁定 15 分钟。
- 锁定期间显示剩余锁定时间，并提供"联系管理员"入口。
- 登录成功后重置失败计数器。
- 首次登录强制修改初始密码。
- 新设备登录发送邮件通知。

#### 6.0.4 密码管理

**密码复杂度要求：**
- 最少 8 位字符，至少包含大写字母、小写字母、数字和特殊字符中的三类。
- 不得包含用户名或邮箱前缀。
- 不得与最近 5 次历史密码重复。

**密码修改：**
- 已登录用户可在"个人设置"中修改密码，需输入当前密码。
- 密码修改成功后销毁除当前设备外的所有会话，并发送邮件通知。

**密码重置（忘记密码）：**
1. 用户在登录页点击"忘记密码"，输入注册邮箱。
1. 系统发送含重置链接的邮件，链接有效期 30 分钟。
1. 用户点击链接进入重置页，设置新密码并确认。
1. 重置完成后销毁该用户所有活跃会话，要求重新登录。
1. 若邮箱未注册，系统仍提示"已发送"，但不实际发送邮件，防止邮箱枚举。

#### 6.0.5 多因素认证（MFA）

**配置：**
- 用户可在"个人设置"中启用或禁用 MFA。
- 支持 TOTP 应用（如 Google Authenticator、Microsoft Authenticator）生成的一次性动态码。
- 启用时需扫码绑定并验证一次动态码，确认绑定成功。
- 禁用 MFA 需输入当前密码和动态码双重确认。

**使用时点：**
- 登录时：密码验证通过后输入动态码。
- 敏感操作（修改密码、导出全量数据、修改评估模型）时可要求二次 MFA 验证，由租户管理员配置。

**恢复码：**
- 启用 MFA 时生成 8 个一次性恢复码，用户应妥善保存。
- 恢复码每使用一个即标记为已用。
- 恢复码耗尽或遗失，需联系租户管理员重置 MFA 绑定。

#### 6.0.6 会话管理

**会话创建：** 用户通过任意方式完成认证后，系统创建服务端会话并下发 HttpOnly + Secure + SameSite=Lax 的 Session Cookie。

**会话超时：**
- 空闲超时：30 分钟无操作后自动失效，用户需重新登录。
- 绝对超时：自登录起 12 小时后强制失效，无论是否活跃。
- 超时前 5 分钟显示续期提醒，用户可选择延长。

**并发会话：**
- 同一用户最多允许 3 个并发活跃会话。
- 超过上限时，最早会话被自动终止。
- 用户可在"个人设置"中查看活跃会话（设备、IP、登录时间）并手动终止。

**会话终止：**
- 用户主动退出登录（登出后清空服务端会话和 Cookie）。
- 密码修改后销毁所有其他会话。
- 管理员强制下线指定用户。

#### 6.0.7 SSO 集成

**配置（租户管理员）：**
- 在"系统管理 → SSO 配置"中填写 IdP 元数据 URL 或上传元数据 XML。
- 支持 SAML 2.0 和 OpenID Connect 两种协议。
- 支持属性映射：将 IdP 返回的字段映射到平台用户属性（邮箱、姓名、角色等）。
- 配置完成后需通过测试登录验证连通性。

**启用与切换：**
- SSO 启用后，登录页新增"企业单点登录"入口。
- 已存在本地密码的用户仍可用原密码登录，直到管理员迁移为纯 SSO 模式。
- SSO 用户不通过平台修改密码；密码策略依赖 IdP 侧规则。

**Just-in-Time 用户创建：**
- 首次通过 SSO 登录且邮箱域名匹配的用户自动创建账号并分配"项目成员"角色。
- 自动创建时需租户管理员审批或预先配置允许的邮箱域名白名单。

#### 6.0.8 审计与通知

以下事件记入审计日志并触发通知（按用户偏好渠道）：

| 事件 | 审计 | 邮件通知 |
| --- | --- | --- |
| 登录成功 | 是 | 仅新设备 |
| 登录失败（含锁定） | 是 | 连续 3 次失败后 |
| 密码修改 | 是 | 是 |
| 密码重置 | 是 | 是 |
| MFA 启用/禁用 | 是 | 是 |
| 会话被管理员终止 | 是 | 是 |
| SSO 配置变更 | 是 | 租户管理员 |
| 账号锁定/解锁 | 是 | 是 |

#### 6.0.9 验收标准

- 用户可通过邮箱 + 密码完成登录，首次登录强制修改密码。
- 连续 5 次密码错误后账号锁定，15 分钟后自动解锁或管理员手动解锁。
- 密码重置链接 30 分钟内有效，使用后即时失效，不可重复使用。
- MFA 绑定、验证、恢复码使用链路完整可用。
- 空闲 30 分钟无操作后刷新页面跳转至登录页，工作数据不丢失。
- SSO 配置完成后，用户可通过企业 IdP 完成登录并自动关联平台账号。
- 所有登录和认证相关事件均写入审计日志，含操作者、时间、IP、User-Agent 和操作结果。
- 用户可在个人设置中查看并手动终止除当前会话外的任意活跃会话。

### 6.1 工作台

工作台按权限展示个人待办、阻断级问题、高风险需求、待确认归因、最近任务和数据源异常。用户可按项目、任务类型、状态和时间筛选并进入任务详情。数据应标明更新时间；无权限内容不得展示名称、摘要或数量。

### 6.2 产品需求价值评估助手

#### 6.2.1 需求录入与校验

评估对象必须是已进入需求池的需求。需求可通过外部系统同步或手工创建，至少包含：

- 需求名称、背景、目标用户及核心场景。
- 预期用户覆盖范围和统计口径。
- 预期业务价值及目标指标。
- 与公司或产品战略的关联说明。
- 预计人力、工期、依赖及技术复杂度。
- 业务、技术、合规和交付风险。
- 需求提出人、负责人及期望上线时间。

系统在提交前校验必填项、数值范围和证据链接可访问性。信息不完整时不得进入正式评估，可保存草稿并生成缺失项清单。

#### 6.2.2 评估模型

平台默认采用五个一级维度，项目管理员可在限定范围内调整权重，但维度不得删除。

| 维度 | 默认权重 | 评分方向 | 主要依据 |
| --- | ---: | --- | --- |
| 用户覆盖 | 20% | 越高越优 | 目标用户数、使用频次、覆盖比例 |
| 业务价值 | 30% | 越高越优 | 收入、成本、留存、效率或风险降低 |
| 战略匹配度 | 20% | 越高越优 | 与年度目标、产品路线及关键项目的关联 |
| 实现成本 | 15% | 越低越优 | 人力、工期、技术复杂度和外部依赖 |
| 风险 | 15% | 越低越优 | 业务、技术、合规、进度及不可逆风险 |

各维度原始分为 1 至 5 分。正向维度换算分为“原始分除以 5 乘以 100”，反向维度换算分为“6 减原始分，再除以 5 乘以 100”。总分为各维度换算分与权重乘积之和，结果保留一位小数。

项目管理员可设置二级指标、评分锚点及权重。一级维度权重之和必须为 100%，单个一级维度权重应在 10% 至 40% 之间。模型修改仅作用于新任务；历史任务保留原模型版本。

**大模型评分机制：** 平台以大语言模型作为评分引擎，而非纯规则计算。对于用户覆盖、业务价值、战略匹配度等依赖文本理解的维度，大模型基于需求描述和评分锚点给出 1-5 分原始分及自然语言解释；对于实现成本、风险等依赖结构化输入的维度，大模型结合人工估算数据和历史项目数据进行辅助判断。人工确认时可直接采纳、修正分数或补充证据。每次评分结果包含大模型版本、所用提示词模板版本及评分锚点版本，确保可复现。

#### 6.2.3 优先级建议

默认优先级规则如下：

| 总分 | 建议优先级 | 处理建议 |
| ---: | --- | --- |
| 80–100 | P0 | 优先进入最近可用版本，必须完成成本与风险复核 |
| 65–79.9 | P1 | 纳入近期规划，明确依赖和资源 |
| 50–64.9 | P2 | 保留在需求池，补充证据后再排期 |
| 0–49.9 | P3 | 暂缓或关闭，记录原因 |

若存在合规红线、关键依赖未解决或风险原始分为 5，系统必须显示风险标记，不得仅凭总分建议 P0。优先级为建议结果，最终优先级由产品负责人确认。

#### 6.2.4 结果展示

评估详情需展示：

- 总分、建议优先级、各维度分数及权重。
- 每项分数的证据引用、缺失信息及系统解释。
- 高影响假设和风险提示。
- 权重上下浮动 10% 后的敏感性结果，用于识别结论是否稳定。
- 同项目候选需求的排名及分差。
- 人工调整前后结果、调整理由和操作者。

系统解释必须引用输入材料，不得只给出抽象判断。证据不足的维度标记为”低置信度”，并说明需要补充的材料。大模型生成的解释须区分”引自输入材料的事实”和”模型基于锚点的推断”，后者应明确标注为推断。

#### 6.2.5 人工确认与审计

产品负责人可接受建议，也可修改维度分、优先级或结论。修改时必须填写理由；涉及 P0 或跨两级调整时，应由另一名有审批权限的成员复核。正式结果包含确认人、确认时间、模型版本、输入快照及变更记录。

#### 6.2.6 验收标准

- 输入完整时，用户可成功创建评估并获得五维评分。
- 权重、反向维度和总分计算结果与规则一致，误差不超过 0.1。
- 每个系统评分均可定位到证据或明确标记证据不足。
- 模型更新后，历史评估结果及版本保持不变。
- 无审批权限用户不能确认或修改正式优先级。

### 6.3 产品交付物一致性检查助手

#### 6.3.1 检查任务创建

用户选择项目和需求后，关联 PRD、原型说明、接口文档、埋点方案和测试用例。每类交付物允许多份文件，但必须指定主版本。系统记录文件名称、来源、版本、更新时间、内容摘要和访问权限。

创建任务时需选择检查范围：

- 全量检查：覆盖全部启用规则，适用于首次提测。
- 增量检查：仅检查相对上一基线的变更内容及其影响范围。
- 指定规则检查：由用户选择字段、流程、权限、异常状态或验收条件。

至少提供 PRD 及另外一类交付物方可执行跨文档检查。材料不足时允许执行单文档完整性检查，但结果必须明确标注”不构成完整一致性结论”。

检查执行时，大模型在规则框架引导下，对多份交付物进行逐维度语义比对。规则定义检查边界和判定标准，大模型负责定位具体冲突位置、提取对照证据、生成问题描述。规则保证检查的结构化一致性，大模型处理跨文档的语义差异识别。

#### 6.3.2 检查维度

| 维度 | 典型检查项 | 示例 |
| --- | --- | --- |
| 字段 | 名称、类型、长度、必填、枚举、默认值、脱敏规则 | PRD 要求手机号必填，接口定义为可选 |
| 流程 | 前置条件、步骤、状态、分支、终止条件 | 原型存在撤回入口，PRD 未定义撤回状态 |
| 权限 | 角色、数据范围、操作权限、审批规则 | 接口允许普通成员删除，PRD 仅允许管理员 |
| 异常状态 | 错误条件、提示、重试、降级、补偿 | 测试用例未覆盖支付超时后的补偿 |
| 验收条件 | 指标、口径、边界、预期结果 | PRD 定义成功率，埋点缺少失败事件 |

检查规则分为通用规则和项目规则。项目规则优先级高于通用规则；规则冲突时必须提示管理员处理，不得静默覆盖。

大模型在此模块中负责跨文档的语义级差异识别。规则引擎保证检查项和判定逻辑的结构化一致性，大模型处理"同一字段在 PRD 和接口文档中定义是否语义等价"这类无法仅靠关键词匹配解决的问题。规则可检测的确定性冲突优先由规则直接判定，降低大模型调用成本和延迟。

#### 6.3.3 问题分级

| 级别 | 判定标准 | 处理要求 |
| --- | --- | --- |
| 阻断 | 可能造成核心流程不可用、越权、数据错误或无法验收 | 提测前必须关闭或由负责人书面豁免 |
| 严重 | 影响重要分支、主要指标或大范围用户体验 | 应在当前版本关闭 |
| 一般 | 影响非核心场景，存在明确替代方案 | 可排期修复，需记录计划 |
| 提示 | 表述不清、轻微缺失或规范建议 | 由责任人判断是否处理 |

系统基于影响范围、发生概率、可恢复性和涉及维度建议级别。责任人可调整级别，但必须填写理由。

#### 6.3.4 检查结果

每个问题应包含：

- 问题标题、检查维度、建议级别和置信度。
- 涉及交付物及精确引用位置。
- 冲突或缺失内容的对照说明。
- 潜在影响、建议修正方向和推荐责任角色。
- 创建时间、状态、责任人、计划完成时间和处理记录。
- 所属检查基线和规则版本。

精确引用至少定位到文档章节、接口字段、埋点事件或测试用例编号。无法精确定位时，系统应降低置信度，不得生成确定性结论。

#### 6.3.5 问题处置流程

问题状态包括待确认、已认领、处理中、待复检、已关闭、已豁免和误报。

1. 系统生成问题后，默认进入待确认。
1. 任务负责人确认问题有效并分配责任人，问题进入已认领。
1. 责任人修正外部交付物，在平台提交修正说明和新材料版本。
1. 系统对相关规则执行复检，通过后进入已关闭，未通过则退回处理中。
1. 若判定为误报，用户必须说明原因，反馈可用于后续规则优化。
1. 若选择豁免，必须填写影响、补偿措施和有效期；阻断级豁免需产品、研发或测试负责人中至少两方确认。

平台不直接覆盖外部文件。关闭问题时必须关联修正后的材料版本，确保结论可追溯。

#### 6.3.6 基线与复检

- 每次正式检查生成不可变基线编号。
- 复检仅使用问题关联规则和新材料，用户也可选择全量复检。
- 新增或删除交付物后必须生成新基线。
- 若材料在分析期间被更新，本次任务继续使用已锁定快照，并提示创建新任务。
- 检查报告显示问题总数、各级别分布、关闭率、未解决阻断项及与上一基线的变化。

#### 6.3.7 验收标准

- 用户可关联五类交付物，并查看来源、版本和同步状态。
- 系统能按五个维度输出问题，并为每个问题提供双向或多向引用。
- 增量检查仅覆盖变更及受影响范围，结果标明对比基线。
- 问题状态流转符合权限和前置条件，关闭后保留完整记录。
- 未解决阻断项存在时，报告明确显示“不可直接通过”的提示。
- 同一输入快照和规则版本重复执行时，关键结论应保持一致。

### 6.4 上线版本问题归因助手

#### 6.4.1 任务创建

创建归因任务时必须填写：

- 项目、发布版本、异常名称和首次发现时间。
- 异常开始与结束时间；未恢复时可不填结束时间。
- 影响范围、用户表现和当前处置状态。
- 关联监控告警、日志查询、工单或缺陷编号。
- 任务负责人和参与角色。

系统自动拉取该版本关联的需求、代码变更、配置变更及测试记录。自动关联失败时，用户可手工补充，但手工材料需标记来源。

#### 6.4.2 分析时间线

系统按统一时间轴排列：

- 需求和设计关键变更。
- 代码合并、构建、发布及回滚。
- 配置、开关和数据任务变更。
- 测试执行及缺陷关闭记录。
- 监控指标突变、告警和关键日志。
- 用户工单、内部反馈及处置操作。

所有事件转换为项目时区展示，同时保留原始时区。无法确定时间的材料进入”待定位证据”，不参与强时序判断。

大模型在此模块中对时间线事件进行语义级归纳，提取异常相关的关键事件并排除噪声。事件排序和时区转换由确定性规则处理，大模型负责判断事件之间的因果关联强度、从日志和工单等非结构化文本中抽取证据片段。

#### 6.4.3 归因类别

系统仅在以下五类中给出候选归因：

| 类别 | 定义 | 典型证据 |
| --- | --- | --- |
| 需求遗漏 | 需求未覆盖必要场景、边界或验收条件 | PRD 缺少异常分支，测试与实现均按原需求执行 |
| 设计缺陷 | 交互、流程、数据或技术方案设计不当 | 已定义场景，但方案在特定条件下必然失败 |
| 实现错误 | 代码实现与已确认需求或设计不一致 | 代码变更引入错误，回滚后指标恢复 |
| 配置变更 | 配置、开关、权限或发布参数不正确 | 配置变更时间与异常开始高度一致 |
| 数据异常 | 输入数据、存量数据、同步或计算结果异常 | 特定数据批次触发问题，代码和配置无变化 |

归因结果允许“一项主要来源加多项促成因素”。当证据无法区分时，应输出多个候选及待验证项，不得强行给出唯一结论。

#### 6.4.4 证据与置信度

每个候选归因包含支持证据、反向证据、缺失证据、时间关系和置信度。置信度分为：

- 高：存在直接证据，时间关系一致，且关键反向证据已排除。
- 中：存在多个间接证据，但仍有未验证假设。
- 低：材料不完整或多个类别均可解释现象。

系统应优先展示可验证事实，将推测与事实分开。日志关键词相关、人员表述或时间接近不能单独构成高置信度结论。

大模型负责从多源非结构化材料中提取证据片段、匹配归因类别并生成自然语言推理链。置信度由大模型基于证据充分性和因果一致性自动评估，同时标注哪些证据"可直接验证"、哪些为"模型推断"。人工确认时可逐证据标记采纳或驳回，反馈用于后续大模型提示词和规则阈值优化。

#### 6.4.5 结果与处置建议

归因详情需展示：

- 异常摘要、影响范围和处置状态。
- 完整时间线及关键转折点。
- 主要来源、促成因素、置信度及证据链。
- 尚未排除的候选来源和建议验证动作。
- 短期止损建议、长期改进建议及建议责任角色。
- 人工确认结论、参与人、确认时间和异议记录。

短期建议可包含回滚、关闭开关、恢复配置、隔离异常数据或增加监控，但平台仅提供建议，不执行生产操作。长期建议应关联到需求模板、设计评审、代码检查、测试覆盖或发布流程中的可执行改进。

#### 6.4.6 人工确认

归因结论必须由任务负责人组织确认。参与者可接受、修正或提出异议；修正必须引用证据。若存在未解决异议，任务可标记“结论有争议”，但不得显示为无争议完成。确认后的结论用于复盘和统计，不作为个人绩效或责任处罚的唯一依据。

#### 6.4.7 验收标准

- 系统可按版本和时间窗聚合六类输入材料。
- 时间线中每条事件均可查看来源、原始时间和关联对象。
- 结果仅使用五类规定归因，并支持主要来源与促成因素。
- 每个候选归因同时展示支持、反向和缺失证据。
- 证据不足时不得输出高置信度或唯一确定结论。
- 用户可修正归因并保留原建议、修改理由及操作记录。

### 6.5 公共能力

- 通过连接器或文件上传接入需求、文档、接口、埋点、测试、代码、发布、监控、日志和工单信息。
- 支持手动及定时增量同步，记录同步范围、结果和失败原因；分析任务始终引用提交时快照。
- 支持按项目、类型、状态、负责人、时间和关键词检索，搜索结果受数据权限限制。
- 任务完成、失败、问题分配、复检失败、阻断项新增及归因待确认时发送通知。
- 正式结果支持导出 Markdown 和表格，导出文件包含任务编号、输入版本、规则版本和生成时间。

## 7. 权限与审计

### 7.1 权限模型

平台采用租户、项目和对象三级权限控制。

| 角色 | 查看 | 创建任务 | 处理问题 | 确认结论 | 项目配置 |
| --- | --- | --- | --- | --- | --- |
| 租户管理员 | 全租户 | 是 | 是 | 是 | 是 |
| 项目管理员 | 所管项目 | 是 | 是 | 是 | 是 |
| 项目成员 | 授权项目 | 是 | 分配范围内 | 按角色授权 | 否 |
| 访客 | 指定对象 | 否 | 否 | 否 | 否 |

对象级权限不得扩大外部数据源原有权限。手机号、身份证号、邮箱、密钥等敏感信息应在分析前脱敏；原始文件、分析结果与导出权限分别控制。

### 7.2 审计日志

以下操作必须记录审计日志：

- 登录、权限变更、数据源连接及连接失效。
- 任务创建、取消、重试和导出。
- 模型、规则、权重及阈值变更。
- 评分、问题级别、豁免及归因结论的人工修改。
- 正式结果确认和复核。

审计记录包含操作者、时间、对象、操作类型、变更前后值和来源地址。普通用户不得修改或删除审计记录。

## 8. 产品指标

### 8.1 成功指标

上线前需记录至少一个完整版本周期作为基线，V1.0 上线后连续观察三个版本周期。

| 指标 | 定义 | 首期目标 |
| --- | --- | ---: |
| 评估覆盖率 | 已完成价值评估的候选需求数除以进入评审的需求数 | ≥ 80% |
| 评估确认时长 | 从提交评估到负责人确认的中位时长 | 较基线降低 30% |
| 提测前问题发现率 | 提测前发现的一致性问题数除以该版本全部同类问题数 | ≥ 70% |
| 阻断问题按期关闭率 | 截止提测前关闭的阻断问题数除以阻断问题总数 | ≥ 95% |
| 一致性检查有效率 | 被确认有效的问题数除以系统问题总数 | ≥ 75% |
| 归因首结论时长 | 从创建任务到产生首个可审查结论的中位时长 | 较基线降低 40% |
| 归因采纳率 | 人工确认时主要来源未发生类别变更的任务占比 | ≥ 70% |
| 任务可追溯率 | 具有完整输入快照、规则版本和确认记录的正式任务占比 | 100% |

指标目标用于验证产品价值，不应以降低问题数量为唯一导向，避免团队隐瞒或减少记录。

## 9. 非功能需求

### 9.1 性能

- 常规列表和详情页面在正常网络下 95% 请求响应时间不超过 2 秒。
- 单个需求价值评估在输入可用后 95% 于 60 秒内完成。
- 单次一致性检查建议上限为 20 份文件、合计 500 页，95% 于 10 分钟内完成。
- 单次版本归因建议时间窗不超过 72 小时、事件数不超过 10 万条，95% 于 15 分钟内产生首个结果。
- 超过建议上限时，系统应在提交前提示拆分范围，不得无提示超时。

### 9.2 可用性与容错

- 核心服务月可用性目标不低于 99.9%，计划维护除外。
- 分析任务采用异步执行，页面关闭不影响任务继续。
- 任务失败后保留已完成步骤和错误原因，支持从安全节点重试。
- 外部数据源不可用时，不影响历史快照和既有报告查看。
- 同一任务的重复提交需具备幂等控制，避免生成重复正式结果。

### 9.3 安全

- 全链路传输加密，敏感数据存储加密。
- 外部数据源凭据采用专用凭据服务管理，不写入日志或导出文件。
- 权限变更在 5 分钟内生效，高风险权限回收应立即生效。
- 文件上传需进行类型、大小及恶意内容检查。
- 租户数据逻辑隔离，检索、缓存和分析结果均带租户标识。

### 9.4 可解释性

- 任何评分、问题或归因结论必须展示所用规则、输入版本和证据。
- 系统生成内容应区分事实、规则判断和推测。
- 低置信度结论必须解释不确定性的来源。
- 用户可对结果提交误报、遗漏或结论错误反馈。
- 模型或规则升级不得改变已确认历史结果。

### 9.5 大模型治理

- 每次分析任务应记录大模型名称、版本、提示词模板版本及温度参数。
- 提示词模板纳入版本管理，修改需经评审并记录变更内容。
- 同一分析任务使用同一模型版本；模型升级后新任务默认使用新版本，历史任务可指定原版本复现。
- 大模型调用需设置单任务 token 上限、超时和重试策略。
- 按任务类型统计大模型调用量、延迟和成本，用于容量规划和成本控制。
- 敏感信息（手机号、身份证号、邮箱、密钥）在送入大模型前必须脱敏处理。

## 10. 异常与边界处理

| 场景 | 处理规则 |
| --- | --- |
| 输入材料无权限 | 阻止提交并列出不可访问对象，不缓存未授权正文 |
| 数据源同步延迟 | 展示最后同步时间，允许使用已有快照或等待同步 |
| 文件解析失败 | 标记失败文件和原因，用户替换文件后重试 |
| 多文档定义冲突且无主版本 | 阻止正式检查，要求指定主版本 |
| 分析期间材料更新 | 当前任务继续使用快照，完成后提示创建新版本 |
| 证据不足 | 输出缺失项和低置信度候选，不生成确定性结论 |
| 规则互相冲突 | 暂停受影响规则，通知管理员处理 |
| 任务超时 | 保留过程状态，支持缩小范围或从失败节点重试 |
| 用户离开项目 | 立即回收访问权，将未完成任务转交项目管理员 |
| 外部对象被删除 | 历史报告保留对象摘要和快照编号，不提供失效原文链接 |

| 阶段 | 范围 |

## 12. 上线准入与验收

### 12.1 上线准入条件

- 三个核心助手的功能验收标准全部通过。
- 阻断级安全、权限和数据隔离缺陷清零。
- 默认模型、规则及五类归因口径完成产品、研发、测试联合评审。
- 至少使用一个真实项目完成端到端试运行。
- 数据源失败、超时、权限回收和历史快照场景完成演练。
- 操作手册、权限说明和问题反馈渠道准备完成。

## 13. 风险与应对

| 风险 | 影响 | 应对策略 |
| --- | --- | --- |
| 输入材料质量低 | 评分和检查结果失真 | 设置完整性门槛，展示缺失项和置信度 |
| 团队将建议视为自动决策 | 引发错误排期或责任争议 | 强制人工确认，明确建议与正式结论状态 |
| 规则误报过多 | 用户放弃使用 | 提供误报反馈、规则停用和按项目调优 |
| 外部系统权限复杂 | 数据泄露或任务失败 | 继承源权限、最小授权、持续校验 |
| 多源时间不一致 | 归因时序判断错误 | 统一项目时区，保留原始时间并标记不确定项 |
| 分析结果不可解释 | 难以采纳和复核 | 所有结论绑定证据、规则和输入快照 |
| 过度关注归责 | 团队减少真实问题记录 | 产品设计聚焦流程改进，不输出个人责任排名 |
| 大文件或高日志量 | 分析超时、成本失控 | 设定范围上限，支持采样、拆分和异步执行 |
| 大模型幻觉 | 评分、问题清单或归因结论中包含虚构证据或错误引用 | 所有结论强制绑定引用位置；无法定位引用时降低置信度并标记为推断；人工确认环节可逐证据驳回 |
| 大模型输出不一致 | 相同输入多次分析产生不同结论，影响可复现性 | 记录大模型版本、提示词版本和温度参数；关键结论使用低温度（≤0.3）；同一快照重复执行结果差异超过阈值时触发一致性告警 |
| 大模型调用成本 | 高并发或大文件场景下 API 调用费用不可控 | 规则可判定的确定性项优先由规则引擎处理；设定单任务 token 上限；支持不同复杂度任务选用不同规模模型 |

## 14. 待确认事项

以下事项缺少原始项目约束，需要在需求评审阶段确认：

- 首批试点团队、项目规模及当前流程基线。
- 优先接入的外部系统、接口能力和授权方式。
- 五个评估维度的默认权重是否适用于目标业务线。
- P0 至 P3 的分数阈值及审批规则。
- 一致性检查的阻断规则、提测门禁和豁免责任人。
- 日志与监控数据允许接入的范围、脱敏要求和保留周期。
- 归因结果的正式确认机制及复盘流程。
- 性能容量、部署方式、可用性目标及合规要求。
- 导出文件的保密级别、水印和外发控制。
- MVP 与 V1.0 的计划时间、人员配置及验收负责人。
