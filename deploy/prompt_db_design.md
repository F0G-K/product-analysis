# 数据库设计提示词

你是一名资深后端架构师和 DBA。请基于本项目的 PRD、概要设计总纲和原型图，完成完整的数据库设计文档。

## 项目背景

产品管理智能助手平台，以大语言模型（LLM）为核心分析引擎 + RAG 检索增强生成技术，提供三个核心助手：
1. **需求价值评估助手** — 从用户覆盖、业务价值、战略匹配度、实现成本、风险五个维度对需求打分
2. **交付物一致性检/查助手** — 跨 PRD/接口/原型/埋点/测试用例进行字段、流程、权限、异常状态、验收条件比对
3. **上线问题归因助手** — 按版本和时间线聚合多源信息，归因到需求遗漏/设计缺陷/实现错误/配置变更/数据异常

技术栈：FastAPI + PostgreSQL 16 + Redis 7 + ChromaDB/Milvus + MinIO/S3 + Celery + LangGraph

## 输出要求

输出一份 Markdown 格式的数据库设计文档，保存在 `docs/4_开发规范/` 目录下，包含以下内容：

### 1. 设计原则
- 租户数据逻辑隔离（所有业务表带 `tenant_id`）
- 分析任务输入快照不可变（保证结论可复现）
- 审计日志完整记录关键操作
- 敏感数据脱敏后再存储
- 模型治理信息与任务绑定

### 2. ER 图（用 Mermaid 语法）
- 画出核心实体关系图，至少覆盖：租户、用户、项目、需求、评估任务、检查基线、检查问题、归因任务、审计日志

### 3. 表结构设计

必须包含以下所有模块的表，每张表注明：字段名、类型、约束、默认值、说明。统一使用以下命名规范：
- 表名：`snake_case` 复数形式
- 主键：`id UUID PRIMARY KEY DEFAULT gen_random_uuid()`
- 时间戳：每表必有 `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` 和 `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`
- 软删除：需要保留记录的表使用 `deleted_at TIMESTAMPTZ`

## 特别注意事项

1. 严格基于 PRD V1.2 中定义的名词、流程、状态和约束
2. 概要设计总纲中的 LangGraph 工作流节点需对应到数据库的任务状态字段
3. 认证模块完整覆盖：密码策略、会话管理、MFA、SSO、审计通知
4. 评估模型的可配置性：支持多维度和权重调整，需版本化管理
5. 一致性检查的基线不可变性：通过快照机制保证
6. 归因模块的五类归因：支持主要来源 + 促成因素的多对多结构
7. 证据链的可追溯性：每个结论必须能追溯到具体引用位置
8. 大模型治理：每次 LLM 调用记录模型版本、提示词版本、温度、token 用量
9. 所有分析任务均可重试，需保留过程状态
10. 审计日志不可修改、不可删除（普通用户）
