# “新建”功能改造实施方案

## 1. 问题与目标

当前“新建项目”“新建评估”“新建检查”“新建归因”和“新建分析”按钮只有样式和文字，未绑定 `onClick`，同时后端未注册项目和业务创建路由。因此不能只修改前端按钮，必须打通前端交互、接口、数据持久化和列表刷新的完整闭环。

改造目标：

- 所有“新建”按钮点击后都有明确响应。
- 创建项目后立即更新项目列表和顶部项目选择器。
- 创建三类分析任务后立即更新对应列表，并进入任务详情。
- 创建过程具备必填校验、防重复提交、成功提示和错误提示。
- 前后端统一任务类型和创建人数据结构。

## 2. 实施策略

本次先实现“最小可用闭环”，不一次性引入需求池、交付物上传、检查基线、发布版本等尚未完成的复杂业务模块。

最小闭环包含：

1. 使用现有 `projects` 表实现项目创建、列表和详情接口。
1. 使用现有 `tasks` 表实现评估、一致性检查和问题归因任务的统一创建。
1. 任务分析输入保存到现有 Redis `AnalysisInputStore`。
1. 任务创建为草稿后进入详情页，用户可显式点击“开始分析”投递到 Celery，避免本地未配置 Worker 或大模型密钥时创建本身失败。
1. 后续再将统一创建弹窗扩展为需求、基线和发布版本的分步向导。

## 3. 前端交互

### 3.1 新建项目

点击“新建项目”打开弹窗，字段包含：

- 项目名称：必填，最长 128 个字符。
- 项目描述：选填。
- 时区：默认 `Asia/Shanghai`。

创建成功后关闭弹窗，刷新 `['projects']` 缓存和 `projectStore`，然后进入 `/projects/{project_id}`。

### 3.2 新建分析任务

三类分析共用一个 `CreateAnalysisDialog`，根据任务类型切换标题、字段文案和默认分析目标。

必填内容：

- 项目。
- 任务标题。
- 分析材料或问题说明。
- 分析目标。

创建成功后根据类型跳转：

| 任务类型 | 跳转地址 |
| --- | --- |
| `assessment` | `/assessment/{task_id}` |
| `consistency_check` | `/consistency/{task_id}` |
| `attribution` | `/attribution/{task_id}` |

项目详情页的“新建分析”使用同一弹窗，自动带入当前项目，并允许选择三种分析类型。

## 4. 后端接口

### 4.1 项目接口

```text
POST /api/v1/projects
GET  /api/v1/projects
GET  /api/v1/projects/{project_id}
```

### 4.2 统一分析任务接口

```text
POST /api/v1/projects/{project_id}/analysis-tasks
POST /api/v1/tasks/{task_id}/dispatch
```

创建请求示例：

```json
{
  "task_type": "assessment",
  "title": "用户画像看板价值评估",
  "description": "评估该需求的业务价值与交付风险",
  "query": "请评估需求价值、成本与风险",
  "input_data": {
    "content": "需求背景、目标用户和核心场景"
  }
}
```

任务创建时绑定当前配置的模型名称和提示词版本，保证现有 AI 工作流的输入校验可以通过。

## 5. 数据与权限

- 项目按 `tenant_id` 隔离。
- 租户管理员可查看和创建租户内项目。
- 项目成员只能为自己有权限的项目创建任务。
- `viewer` 不能创建或投递分析任务。
- 任务创建人和项目管理员可取消、投递或重试任务。

## 6. 错误处理

| 场景 | 处理方式 |
| --- | --- |
| 未选项目 | 表单内联校验，不发送请求 |
| 项目不存在 | 返回 `40401` |
| 权限不足 | 返回 `40302` 或 `40303` |
| 名称或标题为空 | 返回 `42201` |
| Redis 不可用 | 不创建无输入的任务，返回外部服务错误 |
| Celery 投递失败 | 任务进入失败状态并允许后续重试 |
| 重复点击 | 提交按钮进入 `loading` 状态 |

## 7. 验证计划

### 7.1 后端

- 验证项目创建、列表和详情。
- 验证三类任务均可创建为草稿。
- 验证任务输入已写入 `AnalysisInputStore`。
- 验证草稿任务可投递并转为 `validating`。
- 验证未登录请求返回 `401`。

### 7.2 前端

- 执行 `npm run type-check`。
- 执行 `npm run build`。
- 手工验证五个新建入口。
- 验证创建成功后的列表刷新、项目选择器刷新和详情跳转。

## 8. 后续扩展

最小闭环稳定后，再按业务模块增加：

- 需求创建、评估模型选择和评估历史。
- 交付物上传、基线快照和检查规则选择。
- 发布版本创建、异常时间窗和关联告警。
- 详细页的业务结果、证据链、确认和导出功能。
