## 1. 模块概述

### 1.1 模块定位

项目管理与数据源模块是平台的**组织与数据基础设施**。项目管理负责项目的生命周期、成员权限分配；数据源管理负责接入外部系统（PRD 仓库、接口平台、埋点系统、代码仓库、监控、日志、工单），并通过定时或手动同步将外部数据转化为平台可检索的结构化文档。

### 1.2 解决的业务问题

- 多项目隔离：不同项目的数据、成员、评估模型、检查规则相互独立
- 外部数据统一接入：将散落在各系统的文档、日志、工单等信息通过连接器统一拉取、脱敏、索引
- 数据同步追踪：记录每次同步的范围、结果和失败原因，确保分析任务使用的数据版本可追溯

### 1.3 在整体架构中的位置

本模块位于**应用服务层**和**数据与集成层**，为三个核心助手提供项目和数据的上下文支撑。

```
外部系统 ── 连接器 ──► 数据同步 ──► RAG 索引 ──► 核心助手
    │                    │
    └── 项目/成员管理 ────┘
```

## 5. 数据库表与数据模型

> 完整字段定义见 [数据库设计文档 §3.3](../4_开发规范/数据库/数据库设计文档.md)。

### 5.1 涉及的数据表（4 张）

```
projects (1) ──────┬── project_members (N)
                   └── data_sources (N) ──── sync_records (N)
```

### 5.2 核心表摘要

| 表名 | 关键字段 | 特殊约束 |
| --- | --- | --- |
| `projects` | `id, tenant_id, name, description, status, timezone, settings(JSONB)` | 软删除；`status`: active/archived/suspended |
| `project_members` | `id, project_id, user_id, role, joined_at` | `(project_id, user_id)` UNIQUE；`role`: project_admin/project_member/viewer |
| `data_sources` | `id, tenant_id, project_id, name, source_type, connection_config(JSONB, AES-256-GCM), sync_interval, status, last_sync_at, last_sync_status` | `source_type`: prd_repo/api_platform/tracking_system/code_repo/monitoring/logging/ticketing；`connection_config` 加密存储 |
| `sync_records` | `id, data_source_id, sync_type, started_at, ended_at, sync_scope(JSONB), result, items_added/updated/deleted/failed, error_details(JSONB)` | `sync_type`: manual/scheduled；`result`: success/partial/failure；按月分区 |

### 5.3 关键枚举值

**projects.status：**
- `active` — 活跃项目
- `archived` — 已归档（只读）
- `suspended` — 已暂停（不可用）

**project_members.role：**
- `project_admin` — 项目管理员（管理项目配置和成员）
- `project_member` — 项目成员（创建任务、处理问题）
- `viewer` — 访客（只读）

**data_sources.source_type：**
- `prd_repo` / `api_platform` / `tracking_system` / `code_repo` / `monitoring` / `logging` / `ticketing`

**sync_records.result：**
- `success` — 全量成功
- `partial` — 部分成功（部分条目失败）
- `failure` — 完全失败

## 6. 业务逻辑与服务层

### 6.1 ProjectService 核心方法

| 方法 | 职责 |
| --- | --- |
| `create_project(name, description, timezone)` | 校验租户项目数上限 → 创建项目 → 自动添加创建人为 project_admin |
| `get_project(project_id)` | 校验用户是否有该项目的成员关系 |
| `list_user_projects(status, search, page)` | 返回用户有权限的项目列表（分页） |
| `add_member(project_id, user_id, role)` | 校验项目管理员权限 → 添加成员关系 |
| `update_member_role(project_id, user_id, role)` | 校验至少存在一个 project_admin → 更新角色 |
| `remove_member(project_id, user_id)` | 校验不删除最后一个 project_admin → 移除 → 未完成任务转交 |
| `check_project_access(project_id, required_role)` | 通用权限校验（供其他模块调用） |

### 6.2 DataSourceService 核心方法

| 方法 | 职责 |
| --- | --- |
| `create_data_source(project_id, name, source_type, config, sync_interval)` | 加密 connection_config → 创建数据源记录 |
| `test_connection(source_id)` | 解密凭据 → 初始化连接器 → 调用 test_connection() |
| `trigger_sync(source_id, scope)` | 创建 sync_record(draft) → 投递 Celery 任务 |
| `get_sync_history(source_id, page)` | 查询同步历史（分页） |

### 6.3 核心业务流程

#### 6.3.1 数据同步流程

```
定时/手动触发
    │
    ▼
┌──────────────────┐
│ 1. 加密凭据解密   │  CredentialManager.decrypt()
│    (仅内存中使用)  │
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 2. 初始化连接器   │  connector = ConnectorFactory.create(source_type, config)
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 3. 增量变更检测   │  since = last_sync_at；对比外部系统时间戳/版本号
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 4. 拉取变更条目   │  for item in connector.fetch_items(since):
│    (流式处理)     │      masked = masker.mask(item.content)
└────────┬─────────┘      doc = parser.parse(masked)
         ▼                chunks = splitter.split(doc)
┌──────────────────┐      vector_store.add(chunks)
│ 5. 脱敏 → 解析   │
│    → 分块 → 嵌入  │
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 6. 更新同步记录   │  sync_record.ended_at = now()
│    写入结果       │  sync_record.result = success/partial/failure
└──────────────────┘  data_source.last_sync_at = now()
```

#### 6.3.2 成员移除时的任务转交

```
用户被移除项目
    │
    ├── 该用户未完成的任务 → 转交给项目管理员
    ├── 该用户被分配的问题 → 取消分配（assigned_to = NULL）
    └── 审计日志记录
```

### 6.4 连接器基类关键设计

```python
class BaseConnector(ABC):
    """所有连接器的抽象基类"""

    @abstractmethod
    async def test_connection(self) -> dict:
        """返回 {"status": "connected"/"error", "latency_ms": int, "message": str}"""
        ...

    @abstractmethod
    async def fetch_items(
        self,
        since: datetime | None = None,
        scope: dict | None = None,
    ) -> AsyncIterator[SyncItem]:
        """增量拉取变更。since=None 时全量同步"""
        ...

    async def sync(self, db, since=None) -> SyncResult:
        """标准同步流程：拉取 → 脱敏 → 解析 → 分块 → 嵌入 → 入库"""
        ...
```

### 6.5 事务边界

- 项目创建 + 自动添加创建人为 member：同一事务
- 成员移除 + 任务转交：同一事务
- 数据源创建：连接配置加密后写入，无需事务
- 同步流程：拉取、解析、写入分离，失败时记录每条错误

## 7. 权限与安全

### 7.1 权限矩阵

| 操作 | tenant_admin | project_admin | project_member | viewer |
| --- | --- | --- | --- | --- |
| 创建项目 | ✅ | ✅ | — | — |
| 查看项目列表 | ✅（全租户） | 自己管理的 | 自己加入的 | 自己加入的 |
| 修改项目 | ✅ | ✅ | — | — |
| 归档项目 | ✅ | — | — | — |
| 添加/移除成员 | ✅ | ✅ | — | — |
| 管理数据源 | ✅ | ✅ | — | — |
| 查看数据源 | ✅ | ✅ | ✅ | ✅ |
| 触发同步 | ✅ | ✅ | — | — |
| 查看同步记录 | ✅ | ✅ | ✅ | ✅ |

### 7.2 凭据安全

- `connection_config` 中敏感字段（token、password、api_key）使用 Fernet AES-256-GCM 加密后存储
- 解密后的凭据仅在内存中使用，用完立即丢弃
- 凭据不出现在日志、API 响应、导出文件中
- API 响应中 `connection_config` 字段返回 `"***"` 掩码

## 8. 异常处理与边界条件

| 场景 | 处理方式 |
| --- | --- |
| 租户项目数达上限 | 返回 42202 "Project limit exceeded" |
| 创建项目时 slug 冲突（未来扩展） | 返回 40901 |
| 移除最后一个 project_admin | 返回 42202 "Cannot remove the last project admin" |
| 数据源连接测试失败 | 返回详细错误信息和延迟 |
| 同步时外部系统不可达 | 标记 sync_record.result=failure，记录 error_details |
| 同步时部分文件解析失败 | 标记 result=partial，失败条目写入 error_details JSONB |
| 用户离开项目（被移除） | 立即回收访问权，未完成任务转交 |
| 数据源凭据过期 | 连接测试时检测，更新 data_source.status=error |
| 增量同步基准时间丢失 | 降级为全量同步 |
