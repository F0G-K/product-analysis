## 1. 测试策略

### 1.1 测试金字塔

```
         ┌──────┐
         │ E2E  │  ← Playwright（关键用户路径）
         └──────┘
       ┌──────────┐
       │ 集成测试  │  ← React Testing Library（用户交互流程）
       └──────────┘
    ┌────────────────┐
    │   单元测试      │  ← Vitest（工具函数、Hooks、Store）
    └────────────────┘
```

### 1.2 各层职责

| 测试层级 | 工具 | 覆盖目标 | 占比 |
| --- | --- | --- | --- |
| 单元测试 | Vitest | 工具函数、Hooks、Store、类型守卫 | ~60% |
| 组件/集成测试 | Vitest + React Testing Library | 组件交互、表单提交、状态流转、API mock | ~30% |
| E2E | Playwright | 关键用户路径（登录 → 创建任务 → 确认结果） | ~10% |

### 1.3 测试原则

| 原则 | 说明 |
| --- | --- |
| 行为驱动 | 测试用户可见行为，不测试实现细节（state、内部方法名） |
| 独立性 | 每个测试用例独立运行，不依赖执行顺序 |
| 可重复 | 同一输入产生同一结果，不依赖时间、网络等外部状态 |
| 快速反馈 | 单元测试应在毫秒级完成，集成测试在秒级完成 |
| 失败明确 | 失败信息应直接指出预期值与实际值的差异 |

## 2. 技术选型

| 工具 | 用途 | 说明 |
| --- | --- | --- |
| Vitest 4.x | 测试框架 | 与 Vite 深度集成，兼容 Jest API |
| @testing-library/react | 组件测试 | 以用户视角测试组件行为 |
| @testing-library/user-event | 用户交互模拟 | 模拟真实用户操作（点击、输入、键盘） |
| @testing-library/jest-dom | DOM 断言扩展 | `toBeInTheDocument()` 等语义化匹配器 |
| jsdom | DOM 环境 | 在 Node.js 中模拟浏览器 DOM |
| msw (待引入) | API Mock | 拦截网络请求，模拟后端响应 |
| Playwright (待引入) | E2E 测试 | 真实浏览器自动化 |

```bash
npm run test          # 单次运行全部测试
npm run test:watch    # 监听模式，文件变更自动重跑
npm run test:coverage # 运行测试并生成覆盖率报告
```

## 4. 编写规范

### 4.1 测试结构模板

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { render, screen } from '../test/utils'

describe('ComponentName', () => {
  // 1. 渲染测试
  describe('rendering', () => {
    it('renders the component with required props', () => {
      render(<ComponentName requiredProp="value" />)
      expect(screen.getByText('expected text')).toBeInTheDocument()
    })

    it('renders loading state', () => {
      render(<ComponentName loading />)
      expect(screen.getByRole('status')).toBeInTheDocument()
    })

    it('renders empty state when no data', () => {
      render(<ComponentName items={[]} />)
      expect(screen.getByText(/暂无数据/)).toBeInTheDocument()
    })
  })

  // 2. 交互测试
  describe('interactions', () => {
    it('calls onClick handler when button clicked', async () => {
      const onClick = vi.fn()
      render(<ComponentName onAction={onClick} />)
      await userEvent.click(screen.getByRole('button'))
      expect(onClick).toHaveBeenCalledOnce()
    })
  })

  // 3. 边界/异常测试
  describe('edge cases', () => {
    it('handles missing optional props gracefully', () => {
      render(<ComponentName requiredProp="value" />)
      // 不应抛出错误
    })
  })
})
```

### 4.2 查询优先级

按 Testing Library 推荐顺序选择查询方法：

| 优先级 | 查询方法 | 说明 |
| --- | --- | --- |
| 1 | `getByRole` | 最接近辅助技术使用方式 |
| 2 | `getByLabelText` | 表单字段首选 |
| 3 | `getByPlaceholderText` | 仅当没有 label 时 |
| 4 | `getByText` | 非交互文本 |
| 5 | `getByDisplayValue` | 表单当前值 |
| 6 | `getByTestId` | 最后手段，仅无可访问查询时使用 |

### 4.3 断言规范

```typescript
// ✅ 推荐：语义化断言
expect(screen.getByRole('button')).toBeInTheDocument()
expect(screen.getByText('提交成功')).toBeVisible()
expect(button).toBeDisabled()
expect(input).toHaveValue('test@example.com')

// ❌ 避免：测试实现细节
expect(component.state.open).toBe(true)
expect(wrapper.instance().handleClick).toHaveBeenCalled()
```

### 4.4 异步测试

```typescript
// ✅ 使用 findBy* 等待异步渲染
it('loads and displays user name', async () => {
  render(<UserProfile userId="1" />)
  expect(screen.getByRole('status')).toBeInTheDocument() // loading
  const name = await screen.findByText('张三')           // wait for data
  expect(name).toBeInTheDocument()
})

// ✅ 使用 waitFor 等待状态变化
it('shows success toast after submit', async () => {
  render(<AssessmentForm />)
  await userEvent.click(screen.getByRole('button', { name: /提交/ }))
  await waitFor(() => {
    expect(screen.getByText('评估已提交')).toBeInTheDocument()
  })
})
```

## 5. 覆盖率要求

### 5.1 各模块覆盖率目标

| 类别 | 语句 | 分支 | 函数 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 工具函数 (`utils/`) | ≥ 90% | ≥ 85% | ≥ 90% | `format.ts`, `validation.ts`, `cn.ts` 等 |
| 自定义 Hooks (`hooks/`) | ≥ 80% | ≥ 75% | ≥ 80% | `usePagination`, `useDebounce` 等 |
| Zustand Store (`stores/`) | ≥ 80% | ≥ 75% | ≥ 80% | `authStore`, `projectStore` 等 |
| UI 组件 (`components/ui/`) | ≥ 70% | ≥ 60% | ≥ 75% | Button, Modal, Input 等 |
| 业务组件 (`components/{module}/`) | ≥ 60% | ≥ 50% | ≥ 60% | 评估、检查、归因相关组件 |
| 页面组件 (`pages/`) | ≥ 50% | ≥ 40% | ≥ 50% | 关键用户交互路径 |
| API Service (`services/`) | ≥ 70% | ≥ 60% | ≥ 70% | Mock API 响应的集成测试 |

### 5.2 覆盖率豁免

以下文件类型不纳入覆盖率统计：

```typescript
// vitest.config.ts 中已配置排除
coverage: {
  exclude: [
    'src/test/**',          // 测试工具代码
    'src/__tests__/**',     // 测试文件本身
    'src/**/*.d.ts',        // 类型声明文件
    'src/main.tsx',         // 入口文件（仅挂载逻辑）
  ],
}
```

业务代码中如确有无法测试的代码段，使用 `/* v8 ignore next */` 注释标记，但需在 PR 中说明理由。

## 6. Mock 策略

### 6.1 Mock 层级

| Mock 类型 | 工具 | 适用场景 |
| --- | --- | --- |
| 模块 Mock | `vi.mock()` | Mock 第三方依赖、CSS、图片 |
| 函数 Mock | `vi.fn()` / `vi.spyOn()` | 回调函数、事件处理器 |
| API Mock | MSW (待引入) | 拦截 HTTP 请求，模拟后端 |
| 时间 Mock | `vi.useFakeTimers()` | `setTimeout`、`setInterval`、`Date` |
| 存储 Mock | Zustand `setState` 或直接导入 | 预设 Store 状态 |

### 6.2 模块 Mock 示例

```typescript
// Mock CSS 模块（vitest.config.ts 已全局配置，无需手写）
// Mock 图片导入
vi.mock('../assets/logo.png', () => ({
  default: 'mock-logo-url',
}))

// Mock API 服务
vi.mock('../services/assessment', () => ({
  getAssessmentDetail: vi.fn(),
  confirmAssessment: vi.fn(),
}))
```

### 6.3 API Mock（MSW 方案，待引入）

```typescript
// test/mocks/handlers.ts
import { http, HttpResponse } from 'msw'

export const handlers = [
  http.get('/api/v1/tasks/:taskId/assessment', ({ params }) => {
    return HttpResponse.json({
      code: 0,
      message: 'ok',
      data: { task_id: params.taskId, status: 'pending_review', /* ... */ },
    })
  }),

  http.post('/api/v1/auth/login', async ({ request }) => {
    const body = await request.json()
    if (body.password === 'wrong') {
      return HttpResponse.json({ code: 40101, message: '用户名或密码错误' }, { status: 401 })
    }
    return HttpResponse.json({ code: 0, data: { access_token: 'mock-token' } })
  }),
]
```

### 6.4 图表 Mock

ECharts 依赖真实 DOM 测量，在 jsdom 中不可用。测试中用 Mock 替代：

```typescript
vi.mock('echarts-for-react', () => ({
  default: vi.fn(({ option }) => (
    <div data-testid="echarts-mock" data-option={JSON.stringify(option)} />
  )),
}))
```

## 7. 测试用例设计模式

### 7.1 渲染状态覆盖

每个组件至少覆盖以下渲染状态：

| 状态 | 说明 | 必须 |
| --- | --- | --- |
| 默认 | 传入必填 props 的正常渲染 | 是 |
| Loading | 数据加载中的骨架屏/Spinner | 视组件而定 |
| Empty | 空列表/空数据的占位提示 | 视组件而定 |
| Error | 错误状态的提示和重试按钮 | 视组件而定 |
| Edge | 极值输入、超长文本、特殊字符 | 视组件而定 |

### 7.2 表单测试模式

```typescript
describe('LoginForm', () => {
  it('validates required fields', async () => {
    render(<LoginForm />)
    await userEvent.click(screen.getByRole('button', { name: /登录/ }))
    expect(await screen.findByText('请输入邮箱')).toBeInTheDocument()
    expect(await screen.findByText('请输入密码')).toBeInTheDocument()
  })

  it('validates email format', async () => {
    render(<LoginForm />)
    await userEvent.type(screen.getByLabelText('邮箱'), 'invalid')
    await userEvent.click(screen.getByRole('button', { name: /登录/ }))
    expect(await screen.findByText('邮箱格式不正确')).toBeInTheDocument()
  })

  it('submits form with valid data', async () => {
    const onSubmit = vi.fn()
    render(<LoginForm onSubmit={onSubmit} />)
    await userEvent.type(screen.getByLabelText('邮箱'), 'test@example.com')
    await userEvent.type(screen.getByLabelText('密码'), 'Password1')
    await userEvent.click(screen.getByRole('button', { name: /登录/ }))
    expect(onSubmit).toHaveBeenCalledWith({
      email: 'test@example.com',
      password: 'Password1',
    })
  })
})
```

### 7.3 异步任务状态测试模式

```typescript
describe('TaskDetailPage', () => {
  it('shows analyzing spinner while task is running', () => {
    mockTaskResponse({ status: 'analyzing' })
    render(<TaskDetailPage taskId="1" />)
    expect(screen.getByText(/分析中/)).toBeInTheDocument()
  })

  it('shows confirm view when analysis complete', async () => {
    mockTaskResponse({ status: 'pending_review', scores: [...] })
    render(<TaskDetailPage taskId="1" />)
    expect(await screen.findByText(/总分/)).toBeInTheDocument()
  })

  it('shows error view with retry button on failure', async () => {
    mockTaskResponse({ status: 'failed', failure_reason: '数据源不可用' })
    render(<TaskDetailPage taskId="1" />)
    expect(await screen.findByText(/任务执行失败/)).toBeInTheDocument()
    expect(screen.getByRole('button', { name: /重试/ })).toBeInTheDocument()
  })
})
```

## 8. CI 集成

### 8.1 GitHub Actions（建议配置）

```yaml
name: Frontend CI

on:
  pull_request:
    paths:
      - 'frontend/**'

jobs:
  test:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: frontend/package-lock.json
      - run: npm ci
      - run: npm run lint
      - run: npm run test -- --coverage
      - name: Upload coverage
        uses: actions/upload-artifact@v4
        with:
          name: coverage
          path: frontend/coverage/
```

### 8.2 Pre-commit Hook（建议配置）

```bash
# .husky/pre-commit
cd frontend
npm run lint
npm run test -- --changed
```

## 9. 常见问题

### 9.1 jsdom 不支持某些浏览器 API

- **ECharts**: 使用 Mock 替代（见 6.4）
- **matchMedia**: vitest 通过 `css: true` 配置可部分解决
- **ResizeObserver**: 在 `setup.ts` 中添加 polyfill

### 9.2 异步组件测试超时

```typescript
// 增加单测超时
it('long-running async operation', async () => {
  // ...
}, 10_000) // 10 秒超时
```

### 9.3 如何测试使用 React Router 的组件

```typescript
import { MemoryRouter } from 'react-router-dom'

render(
  <MemoryRouter initialEntries={['/assessment/123']}>
    <AssessmentDetailPage />
  </MemoryRouter>
)
```

### 9.4 如何测试使用 React Query 的组件

```typescript
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

const queryClient = new QueryClient({
  defaultOptions: {
    queries: { retry: false }, // 测试中禁用重试
  },
})

function TestWrapper({ children }: { children: React.ReactNode }) {
  return (
    <QueryClientProvider client={queryClient}>
      <MemoryRouter>{children}</MemoryRouter>
    </QueryClientProvider>
  )
}
```
