## 1. 模块概述

### 1.1 模块定位

系统管理与审计模块是平台的**横切能力层**，管理权限控制、审计日志、通知推送、数据导出和 WebSocket 实时通信。它贯穿所有其他模块，为平台提供合规性、可观测性和用户体验支撑。

### 1.2 解决的业务问题

- 统一的权限模型确保数据隔离和操作授权
- 完整的审计日志满足合规追溯要求
- 实时通知确保关键事件及时触达相关责任人
- 标准化导出功能支持离线分析和存档
- WebSocket 推送实现分析任务状态实时更新

**推送事件类型：**

| 事件 | 触发时机 | payload |
| --- | --- | --- |
| `task.status_changed` | 任务状态变更（draft→validating→analyzing→pending_review→completed/failed） | `{task_id, old_status, new_status, timestamp}` |
| `task.progress` | 分析过程中关键节点完成（如"检索完成"、"评分完成"） | `{task_id, node, progress_pct, message}` |
| `issue.created` | 一致性检查发现新问题 | `{issue_id, level, title}` |
| `notification.new` | 新通知 | `{notification_id, type, title}` |
| `data_source.status_changed` | 数据源连接状态变化 | `{source_id, old_status, new_status}` |
| `session.terminated` | 管理员强制下线 | `{reason, timestamp}` |
| `heartbeat` | 心跳保活（每 30s） | `{timestamp}` |

## 5. 数据库表与数据模型

> 完整字段定义见 [数据库设计文档 §3.7](../4_开发规范/数据库/数据库设计文档.md)。

### 5.1 涉及的数据表（6 张）

| 表名 | 用途 | 分区/清理策略 |
| --- | --- | --- |
| `tasks` | 通用任务主表（三类分析任务共享状态机） | 无分区（正式任务快照保留 3 年） |
| `snapshots` | 分析任务输入快照（JSONB 元数据 + MinIO 完整文件） | 与任务同生命周期 |
| `audit_logs` | 操作审计日志（不可修改/不可删除） | 按月分区，热 6 月 + 归档 3 年 |
| `notifications` | 用户通知（站内 + 邮件） | 按月分区，已读 90 天清理 |
| `exports` | 导出记录（关联 MinIO 文件） | 30 天清理 |
| `evidence_items` | 证据条目（事实/推断/缺失） | 与任务同生命周期 |

### 5.2 tasks 核心状态

```
draft → validating → analyzing → pending_review → completed
  │                      │                │
  └── cancelled          ▼                ├── completed (confirmed)
                    failed (可重试)       └── analyzing (修正后重分析)
```

### 5.3 通知类型

| 类型 | 渠道 | 触发条件 |
| --- | --- | --- |
| `task_completed` | 站内 + 邮件 | 分析任务完成，进入待确认 |
| `task_failed` | 站内 + 邮件 | 分析任务失败 |
| `issue_assigned` | 站内 + 邮件 | 一致性问题分配给用户 |
| `recheck_failed` | 站内 + 邮件 | 复检未通过 |
| `blocker_added` | 站内 + 邮件 | 新增阻断级问题 |
| `attribution_pending` | 站内 + 邮件 | 归因任务待确认 |
| `login_new_device` | 邮件 | 新设备登录 |
| `login_failure` | 邮件 | 连续 3 次登录失败 |
| `password_changed` | 邮件 | 密码已修改 |
| `account_locked` | 站内 + 邮件 | 账号已锁定 |

## 6. 审计日志设计

### 6.1 记录范围

按照 PRD 7.2，以下操作必须记录审计日志：

- 登录、权限变更、数据源连接及连接失效
- 任务创建、取消、重试和导出
- 模型、规则、权重及阈值变更
- 评分、问题级别、豁免及归因结论的人工修改
- 正式结果确认和复核

### 6.2 审计日志结构

```json
{
  "id": "uuid",
  "tenant_id": "uuid",
  "operator_id": "uuid",
  "operation": "assessment.confirm",
  "object_type": "task",
  "object_id": "uuid",
  "changes_before": {"status": "pending_review"},
  "changes_after": {"status": "completed"},
  "source_ip": "192.168.1.100",
  "user_agent": "Chrome/120.0",
  "created_at": "2026-07-24T14:30:00+08:00"
}
```

### 6.3 安全约束

- 普通用户不可修改或删除审计记录
- 仅 `platform_admin` 可执行归档操作
- 审计日志查询按 `tenant_id` 隔离（`tenant_admin` 仅见本租户）
- 按月分区，查询跨分区时存在性能降级提示

## 8. 数据导出

### 8.1 导出流程

```
POST /tasks/{id}/export { format: "markdown" | "excel" }
    │
    ▼
1. 校验：任务状态必须为 completed（正式结果才可导出）
2. 创建 Export 记录（status=processing）
3. 异步生成导出文件：
   - Markdown: 基于 Jinja2 模板渲染
   - Excel: openpyxl 生成结构化表格（含评分明细/问题清单/归因时间线）
4. 上传至 MinIO（路径：exports/{tenant_id}/{task_type}/{task_id}/{timestamp}.{format}）
5. 更新 Export 记录（status=completed, file_path, file_size_bytes）
6. 返回 302 下载链接（预签名 URL，5 分钟有效）
```

### 8.2 导出文件内容

导出文件必须包含（PRD 6.5）：
- 任务编号（task_id）
- 输入版本（snapshot_id）
- 规则版本（rule_ids + versions）
- 生成时间
- 完整的分析结果（评分明细 / 问题清单 / 归因证据链）
- 人工操作记录（确认、修正、豁免）

## 9. WebSocket 服务

### 9.1 连接流程

```
1. 客户端: ws = new WebSocket("wss://{domain}/ws?token={jwt}")
2. 服务端: 认证 JWT → 建立连接 → 注册到连接池（user_id → ws）
3. 服务端 → 客户端: {"event": "connected", "user_id": "..."}
4. 按事件推送到已连接用户的 ws
5. 每 30s 心跳（客户端 → 服务端 ping，服务端 → 客户端 heartbeat）
6. 连接断开：自动从连接池移除
```

### 9.2 连接管理

- Redis Pub/Sub 跨 Worker 连接池同步
- 同一用户多设备登录时，每个设备独立的 WebSocket 连接
- 最大连接数 5000（单 Worker 500）

## 10. 权限模型

### 10.1 三级权限体系

| 级别 | 说明 | 实现方式 |
| --- | --- | --- |
| 租户级 | 用户在所属租户内的角色 | `users.role`: `tenant_admin` / `project_member` |
| 项目级 | 用户在项目内的角色 | `project_members.role`: `project_admin` / `project_member` / `viewer` |
| 对象级 | 特定资源（如任务、问题）的权限 | 通过资源的所有者/分配人字段判定 |

### 10.2 权限校验中间件

    task = await task_repo.get_by_id(task_id)

    # 项目权限：校验 project_member 关系
    # 对象权限：viewer 角色只能查看，不能修改

## 11. 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 取消非草稿/待校验状态的任务 | 仅 `draft` 或 `validating` 状态可取消 |
| 重试已完成的任务 | 返回 422 "任务已完成，不支持重试" |
| 导出未完成的任务 | 返回 422 "任务尚未完成正式结果" |
| 通知发送失败（邮件不可达） | 站内通知正常写入，邮件失败记录 WARNING |
| WebSocket 连接数超限 | 关闭最早的空闲连接 |
| 审计日志写入失败 | 记录到 fallback 日志文件，告警触发 |
| 限流触发 | 返回 429 + Retry-After Header |

### 12.2 集成测试

| 场景 | 验证点 |
| --- | --- |
| 审计日志端到端 | 操作触发 → 审计记录写入 → 查询可见 → 不可修改 |
| 通知端到端 | 任务完成 → 站内通知 → WebSocket 推送 → 标记已读 |
| 导出端到端 | 评估确认后 → 导出 Markdown → 下载文件内容完整 |
| WebSocket 端到端 | 任务状态变更 → WebSocket 推送 → 客户端收到事件 |
| 限流 | 超过 100 次/分钟 → 429 返回 + Retry-After |

### 12.3 PRD 验收标准覆盖

- 权限变更在 5 分钟内生效，高风险权限回收应立即生效
- 审计记录包含操作者、时间、对象、操作类型、变更前后值和来源地址
- 普通用户不得修改或删除审计记录
- 正式结果导出包含任务编号、输入版本、规则版本和生成时间
- 导出文件的保密级别控制
