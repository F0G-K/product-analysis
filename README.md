# 产品管理智能助手平台

## 项目简介

做产品时，团队常常遇到三个头疼的问题：**需求优先级靠拍脑袋**、**各角色文档对不上**、**线上出问题定位慢**。

这个平台以大语言模型为核心分析引擎，用 RAG（检索增强生成）技术把散落在各处的信息串起来，给出带证据的建议，最后拍板的还是人。

平台提供三个助手：

**1. 需求价值评估助手**
给每个需求从五个维度打分 — 覆盖多少用户、能带来多少业务价值、跟公司战略合不合拍、实现成本高不高、有什么风险。综合算出一个分数，推荐该不该优先做。分数怎么来的、哪项证据不足，一目了然。

**2. 交付物一致性检查助手**
产品、开发、测试各写各的文档，PRD、接口定义、埋点方案、测试用例之间经常互相矛盾。这个助手自动比对字段、流程、权限、异常处理是否一致，在提测前把问题揪出来，避免联调或上线后才返工。

**3. 上线问题归因助手**
线上出异常了，日志、监控、工单、代码变更散在各处。这个助手按版本和时间线把所有材料串起来，告诉你问题最可能是需求遗漏、设计缺陷、实现错误、配置变更还是数据异常，每条结论都附上证据链和可信度。

---

**一句话总结：** 不做自动决策，只做有据可查的分析 — 让每个需求优先级有说法、每次文档不一致有清单、每次线上故障有归因。

## 技术架构

基于 **LangGraph + RAG（检索增强生成）** 技术路线。

- **编排层**：LangGraph 有状态图工作流，实现多步骤分析任务的条件分支、并行检索、人工确认中断和断点续跑
- **检索层**：ChromaDB / Milvus 向量数据库 + BM25 关键词混合检索 + Cross-encoder 重排序
- **推理层**：Claude API（可替换），温度 ≤0.3，关键结论绑定证据引用
- **规则引擎**：自研 Python DSL，确定性冲突优先由规则判定，降低 LLM 调用成本
- **后端**：FastAPI + Celery + Redis + PostgreSQL 16
- **前端**：HTML5 + Tailwind CSS（原型阶段）

## 本地运行

### 原型图

```bash
cd docs/2_原型图
open index.html   # 或直接浏览器打开
```

### 后端

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m backend
```

启动后可访问：

- 健康检查：<http://localhost:8000/health>
- Swagger 接口文档：<http://localhost:8000/docs>
