## 1. 模块概述

### 1.1 模块定位

用户认证与登录模块是平台的**安全入口**，负责用户身份验证、会话管理和访问控制。平台支持本地账号和 SSO 两种认证方式，并提供 MFA（多因素认证）增强安全性。所有登录活动纳入审计日志，会话受超时和并发策略约束。

### 1.2 解决的业务问题

- 确保只有经过认证的用户才能访问平台资源
- 防止未授权访问和凭证爆破攻击
- 支持企业 SSO 集成，降低多系统登录的摩擦
- 通过 MFA 提供额外的安全层
- 完整的审计追踪满足合规要求

### 1.3 在整体架构中的位置

本模块位于**接入层**和**应用服务层**，是平台的第一道安全防线。所有其他模块的 API 请求均需通过本模块的认证中间件校验。

```
用户 → Nginx (TLS) → FastAPI 认证中间件 → [本模块] → 下游业务模块
                           │
                    验证 JWT / Session Cookie
                    注入 tenant_id + user 上下文
```

### 5.1 涉及的数据表（9 张）

```
tenants (1) ──────┬── users (N) ──────┬── user_sessions (N)
                  │                   ├── mfa_configs (1)
                  │                   ├── mfa_recovery_codes (N, max 8)
                  │                   ├── password_reset_tokens (N)
                  │                   └── login_audit_logs (N)
                  │
                  ├── sso_configs (1)
                  └── invitations (N)
```

### 5.2 核心表摘要

| 表名 | 关键字段 | 特殊约束 |
| --- | --- | --- |
| `tenants` | `id, name, slug, admin_user_id, status, max_users, max_projects, settings(JSONB)` | `slug` UNIQUE，软删除 |
| `users` | `id, tenant_id, email, password_hash, name, role, is_first_login, locked_until, failed_login_count, auth_provider, sso_external_id` | `(tenant_id, email)` UNIQUE；SSO 用户 `password_hash` 可为 NULL |
| `user_sessions` | `id, user_id, token_hash, device_info, ip_address, expires_at, is_active, terminated_reason` | `token_hash` UNIQUE |
| `mfa_configs` | `id, user_id, totp_secret_encrypted, is_enabled, bound_at, last_used_at` | `user_id` UNIQUE；密钥 AES-256-GCM 加密 |
| `mfa_recovery_codes` | `id, mfa_config_id, code_hash, is_used, used_at` | 每个 mfa_config 最多 8 条 |
| `sso_configs` | `id, tenant_id, protocol, idp_metadata_url/xml, idp_certificate, attribute_mapping(JSONB), allowed_email_domains, jit_provisioning, is_enabled` | `tenant_id` UNIQUE |
| `password_reset_tokens` | `id, user_id, token_hash, expires_at, is_used, used_at` | 创建新令牌时旧令牌自动失效 |
| `invitations` | `id, tenant_id, inviter_id, email, token_hash, expires_at, is_activated, activated_user_id` | 48h 过期；同邮箱 24h 内最多 3 次 |
| `login_audit_logs` | `id, tenant_id, user_id, email, operation, result, failure_reason, ip_address, user_agent` | 按月分区，不可修改/不可删除 |

### 5.3 关键枚举值

**users.role（租户级角色）：**
- `tenant_admin` — 租户管理员，可管理租户内所有项目、用户和配置
- `project_member` — 项目成员，权限由项目内角色决定

**users.auth_provider：**
- `local` — 本地密码认证
- `sso` — 单点登录（密码字段可为 NULL）
- `ldap` — LDAP 认证

**user_sessions.terminated_reason：**
- `logout` / `timeout` / `password_change` / `admin_force` / `concurrent_limit`

**login_audit_logs.operation：**
- `login` / `logout` / `password_change` / `password_reset` / `mfa_enable` / `mfa_disable` / `session_terminated` / `account_locked` / `account_unlocked` / `sso_config_change`

## 6. 业务逻辑与服务层

### 6.1 AuthService 核心方法

| 方法 | 职责 |
| --- | --- |
| `login(tenant_slug, email, password, remember_me)` | 验证凭证 → 检查 MFA → 签发 JWT + Session → 记录审计 |
| `verify_mfa(mfa_token, code)` | 验证 TOTP/恢复码 → 完成登录 → 签发正式 Token |
| `logout(user_id, session_id)` | 标记会话终止 → 清除 Cookie |
| `change_password(user_id, old_pw, new_pw)` | 验证旧密码 → 验证强度策略 → 更新哈希 → 销毁其他会话 |
| `initiate_password_reset(tenant_slug, email)` | 生成 token → 发邮件（防枚举：无论是否存在都返回成功） |
| `reset_password(token, new_pw)` | 验证 token → 更新密码 → 标记已用 → 销毁该用户所有会话 |
| `bind_mfa(user_id, password)` | 验证密码 → 生成 TOTP 密钥 → 生成 8 个恢复码 → 返回 QR URL |
| `confirm_mfa_bind(user_id, code)` | 验证 TOTP → 标记 is_enabled=true |
| `process_sso_callback(tenant_slug, saml_response)` | 验证断言 → 查找/创建用户（JIT） → 签发 Token |
| `check_session_timeout()` | 定时任务：标记过期会话 → 清理 30 天以上已终止会话 |

### 6.2 核心业务流程

#### 6.2.1 登录流程

```
用户提交 { tenant_slug, email, password }
    │
    ├── 1. 查找 tenant（slug → tenant_id）
    ├── 2. 查找 user（tenant_id + email），不存在 → 401（不提示具体原因）
    ├── 3. 检查 locked_until，已锁定 → 40104
    ├── 4. 验证密码（bcrypt），失败：
    │       failed_login_count += 1
    │       if failed_login_count >= 5: locked_until = now() + 15min
    │       写入 login_audit_logs（result=failure）
    │       → 40101
    ├── 5. 密码验证成功：
    │       failed_login_count = 0, locked_until = NULL
    │       检查 is_first_login → 强制要求修改密码
    │       检查 mfa_configs.is_enabled → 40105（需 MFA）
    ├── 6. 签发 JWT（30min）+ Session Cookie（12h）
    ├── 7. 创建 user_session 记录
    ├── 8. 写入 login_audit_logs（result=success）
    └── 9. 返回 access_token + user 信息
```

#### 6.2.2 密码重置流程

```
用户 POST { tenant_slug, email }
    │
    ├── 查找 user，不存在 → 仍返回 200 "已发送"（防枚举）
    ├── 生成 token（SHA-256），expires_at = now() + 30min
    ├── 旧未使用 token 自动失效（is_used=true）
    ├── 发送邮件（含重置链接）
    └── → 200 "已发送"

用户 POST { token, new_password }
    │
    ├── 验证 token 存在、未使用、未过期
    ├── 验证密码强度（vs 租户 password_policy）
    ├── 验证不与最近 5 次历史密码重复
    ├── 更新 password_hash，password_changed_at = now()
    ├── 标记 token.is_used = true
    ├── 销毁该用户所有活跃会话（terminated_reason='password_change'）
    ├── 写入 login_audit_logs
    └── → 200 "密码已重置，请重新登录"
```

#### 6.2.3 SSO 登录流程

```
用户 GET /api/v1/auth/sso/{slug}/login
    │
    ├── 查找 sso_configs（tenant_id, is_enabled=true）
    ├── 构造 SAML AuthnRequest / OIDC Authorization URL
    └── → 302 重定向至 IdP 登录页

IdP 回调 POST /api/v1/auth/sso/{slug}/callback
    │
    ├── 验证 SAML Response 签名（idp_certificate）
    ├── 提取用户属性（按 attribute_mapping 映射）
    ├── 查找 user（tenant_id + sso_external_id / email）
    │   ├── 已有用户 → 直接登录
    │   └── 无用户 + jit_provisioning=true + email 域名在白名单
    │       → 自动创建用户（auth_provider='sso', role='project_member'）
    ├── 签发 JWT + Session Cookie
    └── → 200 access_token + user
```

### 6.3 权限校验

- 租户管理接口仅 `platform_admin` 角色可访问（系统级角色，不属于任何租户）
- 用户管理接口需 `tenant_admin` 角色（租户级）
- 会话管理接口仅允许操作自己的会话
- 所有 UserService 方法自动注入 `tenant_id` 过滤

### 6.4 事务边界

- 登录操作：验证 + 会话创建 + 审计日志写入在同一事务中
- 密码重置：token 标记 + 密码更新 + 会话销毁在同一事务中
- 邀请激活：token 验证 + 用户创建在同一事务中
- 租户创建：tenants 写入 + admin 用户创建 + 初始项目创建在同一事务中

| 策略 | 实现 |
| --- | --- |
| 密码存储 | bcrypt 哈希（passlib），永不明文存储 |
| 密码强度 | 最少 8 位，大写/小写/数字/特殊字符至少三类；不与近 5 次重复 |
| 传输安全 | 全链路 TLS 1.3；Session Cookie 标记 HttpOnly + Secure + SameSite=Lax |
| JWT | HS256 签名，30 分钟过期，payload 含 sub/tenant_id/role |
| TOTP 密钥 | AES-256-GCM 加密存储于 `totp_secret_encrypted` |
| 恢复码 | SHA-256 哈希存储（`code_hash`），仅绑定瞬间返回明文一次 |
| 登录限流 | 连续 5 次失败锁定 15 分钟；密码重置接口同 IP 5 次/10 分钟 |
| 防枚举 | 登录失败不区分"用户不存在"和"密码错误"；密码重置未注册邮箱同样返回成功 |
| 会话安全 | 密码修改后销毁所有其他会话；管理员可强制下线指定用户 |
| 新设备通知 | `login_audit_logs` 中 `device_fingerprint` 对比 → 新设备发邮件通知 |

### 7.3 租户隔离

- `users` 表 `(tenant_id, email)` 唯一索引确保跨租户邮箱可重复
- 所有查询通过 `tenant_id` 过滤
- 认证时先根据 `tenant_slug` 确定租户上下文

## 8. 异常处理与边界条件

### 8.1 异常场景

| 场景 | 错误码 | HTTP 状态 | 处理方式 |
| --- | --- | --- | --- |
| 登录凭证无效 | `40101` | 401 | 不区分用户不存在/密码错误 |
| Token 过期 | `40102` | 401 | 前端刷新或重新登录 |
| 会话已失效 | `40103` | 401 | 重定向到登录页 |
| 账号已锁定 | `40104` | 401 | 返回 `locked_until` 时间，显示倒计时 |
| 需要 MFA 验证 | `40105` | 200 | 返回 `mfa_token`，引导进入 MFA 流程 |
| MFA 验证失败 | `40106` | 401 | 允许重试；使用恢复码时标记已用 |
| 租户权限不足 | `40301` | 403 | 不在该租户的用户 |
| SSO 配置错误 | `50003` | 502 | 记录详细错误，提示联系管理员 |
| 密码策略不满足 | `42201` | 422 | 返回具体不满足的规则列表 |
| 重置令牌过期 | `40101` | 401 | 引导重新发起重置 |
| 并发会话超限 | `40103` | 401 | 自动终止最早会话 |
| 邀请链接已过期 | `40401` | 404 | 引导管理员重新发送 |
| 同邮箱重复邀请 | `40901` | 409 | 24h 内最多 3 次 |

### 8.2 超时与重试

- 登录接口 30 秒超时
- 邮件发送（重置/邀请）异步执行，失败后重试 3 次
- SSO IdP 回调 60 秒超时
